# Paladin — AGI 时代的最小可执行架构范式

> **分工明确 + 闭环生长 + 树形演进**
> 不依赖 AGI 是否到来。适用于今天所有 AI 项目。

---

## 我们在构建什么？

> 一个让 AI 项目复杂度可管理、不熵增的架构范式。

不是框架。不是库。是一套可执行的**架构规则**，让你在任何 AI 项目中都能回答三个问题：

| 问题 | 树的回答 |
|------|---------|
| 现在在哪？ | 树干→分枝→叶片，精确位置 |
| 要去哪？ | 北极星（树干）决定方向 |
| 下一步做什么？ | 当前分枝上未闭环的叶子 |

## 三大范式支柱

### 🛡️ 分工明确 — Commander / Dispatcher

决策与执行分离，不混淆。

| 层 | 命名 | 职责 | 类比 |
|----|------|------|------|
| 大脑 | Commander | 理解意图、拆解任务、规划步骤 | 将军 |
| 手脚 | Dispatcher | 路由、限流、容错、状态追踪 | 传令兵 |
| 护甲 | 三篱笆 (Cache/Router/Watch) | 缓存命中、模型路由、成本监控 | 盾牌 |

### 🔄 闭环生长 — 生成 → 验证 → 修复 → 持久化

每一次迭代都留下可用的产物。

```
用户说"提取标题"
  → Planner: 检测到工具 extract_title 不存在 → 触发合成
  → CodeGenerator: 生成 Python 函数代码
  → Validator: 沙箱执行测试用例（零依赖）
  → Loader: 动态注册到运行时
  → Executor: 执行工具，返回结果
  → 工具已持久化到 generated_tools/，下次直接可用
```

### 🌳 树形演进 — 版本 → 枝叶 → 文件

让系统复杂度可管理，不熵增。

```
🌳 Paladin
│
├── 🌱 会执行 (v0.1-v0.7)  ← 已闭环
│   └── 三篱笆 / 指挥官-调度官 / 配置化
│
├── 🌿 会创作 (v0.8)       ← 已闭环
│   └── 工具合成 / 热加载 / 持久化 / 自主缺位检测
│
└── 🌳 会进化 (v1.0)       ← 生长中
    └── 沙箱验证 (v0.9.1)
```

## 反模式对照

| 堆砌模式 ❌ | 树形模式 ✅ |
|------------|------------|
| "先写着，后面再重构" | "先画树，再落第一片叶" |
| "这个功能以后可能用上" | "这个功能属于哪枝？不在树上就不写" |
| "改一个文件顺便修另一个" | "只动当前分枝的当前叶" |
| "版本推进不顺就回溯" | "分枝锁死后不回溯" |
| "新功能直接叠加上去" | "找到对应分枝，长新叶" |

## 文件结构

```
paladin/
├── commander/       # 决策层
│   ├── planner.py   # 规划器（含 Mock 模式缺位检测）
│   └── protocol.py  # 接口协议（PlanStep / MetaAction / ExecutionResult）
├── dispatcher/      # 执行层
│   └── executor.py  # 执行器（chain/parallel/branch + 工具合成）
├── models/          # 三篱笆
├── adapters/        # 模型适配器
├── codegen.py       # 工具代码生成器
├── loader.py        # 动态模块加载器
├── validator.py     # 沙箱验证器
├── config.py        # 配置系统
├── app.py           # 入口 + 6 场景演示
├── paladin.toml     # 默认配置
├── generated_tools/ # 持久化工具目录
└── docs/
    ├── ARCHITECTURE.md     # 三阶跃迁路线图
    └── TREE_METHODOLOGY.md # 树状架构开发方法论
```
